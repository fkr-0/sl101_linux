## Verified boot path

A read-only copy of the physical eMMC LNX slot at byte offset 8,912,896
(length 8,388,608 bytes / 8 MiB) contained the exact previously running
stock zImage (SHA-256 794a3766aed121654aed5b88f3a8d826f38b47fa4fcfb5bb01d3267518a0d9e1)
and appended SL101 DTB (SHA-256
01fbb5a935e429c42dc5e2793049bbfc91ff3a6f73c15f2063e1fb0af1a289b0)
in a 2,048-byte Android-header LNX container. After replacing **only**
the LNX kernel payload, a normal reboot loaded the new kernel. Thus
**the .106 eMMC LNX kernel path is operative**, regardless of whether
the installed first-stage firmware identifies as U-Boot or ASUS-derived.
The SD extlinux default was NOT the controlling normal boot entry.

The original Android-header SHA-1 ID was not consistent with the
generic offline builder's standard formula even for the bootable stock
image. We preserved its working header format and used the repository's
device-local sl101-rawboot.py v2, which changes the kernel-size field and
the appended zImage/DTB payload, not an incompatible mkbootimg guess.
Written payload including header was 6,552,646 bytes, **inside the
8,388,608-byte LNX slot**. No adjacent boot partitions were written.
