# Cog URL entry and GPU qualification, 2026-10-04

## Installed URL control

Use **Super+U**, or **Apps -> Cog: Open URL**, to open a Wayland-native bemenu
prompt. Enter a full HTTP/HTTPS URL or a domain; domains receive `https://`.
Escape cancels. If Cog is running, `cogctl open` is executed against that
browser's own private D-Bus session without restarting its process. If idle,
the helper starts the root-owned configured mode in a detached session.

Installed files:

- `scripts/sl101-cog-url` -> `/usr/local/bin/sl101-cog-url`;
- `scripts/sl101-cog-control.py` -> `/usr/local/sbin/sl101-cog-control`;
- `scripts/sl101-cog-session` -> `/usr/local/libexec/sl101-cog-wpe-enter`.

The helper validates tablet hostname, kernel and SD CID, restricts URLs to
HTTP/HTTPS without embedded credentials, passes argv without shell evaluation,
and drops to browser UID 1000 for the control command. The native prompt uses
the installed Alpine bemenu package, with a foot prompt fallback. The existing
desktop entry now opens the prompt. A W-u keybind was added alongside labwc's
default bindings; the touchscreen calibration subtree is unchanged.

Navigation was verified in the running software Cog session: the browser PID
stayed 32532 while the local fixture changed from `/` to `/second` and loaded.
The prompt was captured visibly on Wayland. VNC simulated typing dropped
characters; native keyboard entry requires user review and this transport result
is not claimed as successful typed-URL qualification.

## GPU result: rejected for normal browsing

GPU-mode Cog and WebProcess mapped the new private Grate libraries and opened
`/dev/dri/renderD128`. This is initialization evidence, not successful GPU
browser presentation.

- GPU compatibility composition mode: page load completed, but no page appeared
  and the WebGL animation fixture never posted its result.
- GPU Skia composition mode: same missing presentation/result.
- Fresh GPU test without WebGL: JavaScript timer posted after 8006 ms, reporting
  **zero requestAnimationFrame callbacks**. The page still did not appear.
- The WebGL runs logged `GL_INVALID_ENUM` for
  `GL_MAX_VERTEX_UNIFORM_COMPONENTS`; the plain CSS/JS failure did not require
  that probe, so this message is not established as the root cause.
- No new matching GPU/kernel faults were observed and visible labwc 24764
  survived. Desktop renderer and boot selection were unchanged.

The software fixture produced 2 frames in 7302 ms on its first run and 7 frames
in 6089 ms on a repeated run. This small local animation test confirms severe
sluggishness, but is not a general browser benchmark. The WebGL renderer string
reported by the page was not used as hardware provenance.

`/etc/sl101-cog-mode` remains `software`. Software Cog was restored at Wikipedia
with PID 1449 / WebProcess 1475 and logged a successful page load. Its two
`DRM_IOCTL_MODE_CREATE_DUMB failed: Permission denied` warnings remain unresolved.
The next GPU investigation is first-buffer/presentation and frame-callback
handoff between WebKit, WPEBackend-fdo, Cog and Wayland; relaxing a pixel gate
or claiming GPU success from mapped libraries would be incorrect.

## Operations and recovery

CLI navigation:

```sh
sudo /usr/local/sbin/sl101-cog-control open https://de.wikipedia.org/
```

Explicit diagnostic modes are `software URL` and `gpu URL`; close the existing
browser before switching. GPU is not the default. The controller holds the
shared qualification lock for the browser lifetime, so close Cog before a
renderer switch or another graphics experiment.

Backups of the enter helper, desktop entry and original labwc rc.xml are under
`/var/lib/sl101-cog-url-backup/`. The original Grate overlay and software path
are retained. Local validation: 98 tests and syntax checks pass. The long-term
browser soak and native keyboard entry still need review.
