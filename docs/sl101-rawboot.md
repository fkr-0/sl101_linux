# SL101 guarded raw boot-slot updater

Live evidence established the current persistent Linux payload on the SL101 internal eMMC:

- device: /dev/mmcblk0
- zImage byte offset: 8914944
- current zImage SHA-256: aaf847d5a15a5c673d921f87c3c08d45dd7ddff8185723dd7da804289265d630
- zImage declared size: 8106984 bytes
- adjacent DTB byte offset: 17021928
- current DTB SHA-256: 7c938df062396a142f800c3807ba0d8f4255cd9ff8bfc8d09e83ee93b1dcb52a
- the current DTB lacks embedded-controller@19
- the EC kernel+DTB pair was validated by kexec and produced a working physical keyboard

scripts/sl101-rawboot.py exists to avoid one-off dd operations.

## Safety model

The tool is read-only unless write or restore is explicitly selected. Persistent writes require an explicit live-evidence slot size, exact current kernel and DTB hashes, a backup destination, and the confirmation token generated by plan.

Do not invent --slot-size. Determine the slot boundary from fresh live-device evidence first.

Inspect:

    sudo scripts/sl101-rawboot.py inspect --device /dev/mmcblk0 --offset 8914944

Plan:

    sudo scripts/sl101-rawboot.py plan \
      --device /dev/mmcblk0 \
      --offset 8914944 \
      --slot-size LIVE_EVIDENCE_SLOT_SIZE \
      --kernel /path/to/validated/zImage \
      --dtb /path/to/validated/tegra20-asus-sl101.dtb \
      --expected-kernel-sha256 aaf847d5a15a5c673d921f87c3c08d45dd7ddff8185723dd7da804289265d630 \
      --expected-dtb-sha256 7c938df062396a142f800c3807ba0d8f4255cd9ff8bfc8d09e83ee93b1dcb52a

Write first backs up the entire declared slot, fsyncs it, records a manifest and SHA-256, writes only kernel||dtb, fsyncs, then verifies the target pair by readback.

Restore uses the exact saved slot image and a separate content-derived confirmation token.

## Invariants

- Never infer write geometry from TF101 layouts or historical partition guesses.
- Never write unless current hashes match the live-observed baseline.
- Never write a target kernel+DTB pair that has not first been validated non-persistently.
- Never bypass the backup or confirmation token.
- Never partition or reformat eMMC.
- Preserve the SD Debian rootfs and a known-good boot/recovery path.
