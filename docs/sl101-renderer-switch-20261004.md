# SL101 compositor controls

The panel badge observes the running labwc PID, renderer environment and mapped private Mesa library. Generic GLES2 remains labelled GLES2; unreadable/stale process state is Unknown. It does not describe the browser's renderer.

The System menu offers confirmed Pixman and experimental Grate restarts when the installed panel is launched with `--enable-renderer-switch`. A restart closes application windows. The root-owned helper accepts exactly `pixman` or `grate`, validates the device hostname and exact kernel/library set, and refuses while `/run/lock/sl101-nura-qualification.lock` is occupied. It returns promptly, holds the lock in a detached worker, stops WayVNC then labwc, writes only `/run/sl101-desktop-renderer.conf`, checks the new compositor and restarts WayVNC. Failed Grate startup recovers Pixman. Logs: `/var/log/sl101-renderer-switch.log`.

Boot remains Pixman. Candidate Mesa gallium SHA256 is `68a78e18af642275d3fec6fc93a4f20cd618d9f951981c7e240d5731e7f29ade`; this is a reversible trial, with known pixel differences, not a pixel-qualified default.

The launcher now explicitly exports German XKB layout before labwc starts. The prior user environment file already contained `XKB_DEFAULT_LAYOUT=de`, but the service process did not inherit it in its startup environment. This hardens service and alternative-config restarts; the intermittent English report still requires input-device reproduction to establish its precise cause. WayVNC was running without XKB_DEFAULT_LAYOUT and its config had no xkb_layout: its independently supplied virtual keyboard could introduce English when VNC connected. The WayVNC service now uses `-k de`. VT loadkmap and keyd remain separate.

Cog review currently forces software mode. GPU Cog uses its separate glibc Mesa stack inside Debian; selecting Grate for labwc alone does not accelerate WebKit. KMS dumb-buffer permission messages do not establish GPU rendering. The GPU branch also needs the same no-SIMD WebP libraries that made the software pages stable.

Deployment: run `scripts/sl101-renderer-controls-deploy.sh` from the host checkout. It installs the helper, read-only verifier and service snapshots; copies the pinned Mesa runtime into root-owned `/usr/local/lib/sl101-grate-68a…` so a development-owned `/opt` directory cannot replace the selected libraries; verifies hashes and symlink targets; and leaves labwc running. Install a reviewed ARMv7 Nura binary set with `sl101-panel-install.sh`, and use the supplied session autostart to enable confirmed switching. Restarting only WayVNC applies `-k de` without closing applications.
