as one "kernel patch set":

   started as an inherited Grate Gallium implementation, was ported onto Mesa
   25.0.7, and then accumulated project-specific compiler, resource, texture,
   synchronization, blend, scissor, and compositor fixes. The latest visually
   accepted binary still lacks the exact-hash full compositor oracle/soak gate.
4. **Nura packaging — separate from Mesa source and Linux.** The local
   `mesa-grate-sl101` pmaports recipe is untracked and packages a local
   `ported-source.tar.gz`; it is not submission-ready.
5. **Session configuration — local integration.** Renderer selection, private
   `/opt` prefixes, rollback-to-pixman policy, WayVNC restart logic, and browser
   software-rendering constraints are deployment/session concerns, not Linux or
   Mesa patches.

### K2 — Transformer EC serio response framing/routing

**Ownership:** project-specific correction on top of the public series.

**Root cause / reproduction:**

- observed reset response: `03 09 fa aa`;
- count byte `03` covers status `09`, ACK `fa`, BAT-success `aa`;
- v10's `data[0] - 2` drops the final payload byte;
- valid keyboard command responses can be OBF-only without KEY/KBC, so dropping
  those packets prevents PS/2 ACKs reaching `atkbd`;
- corrected builds passed real keyboard testing, including ordinary/modifier/
  special keys, repeat, slider switch, and a resume cycle on the cleaned
  upstream-form build.

**Prepared change:**

- `docs/upstream/sl101-ec-v10/v10-3-serio-fix-keyboard-responses.diff`

**Upstream target / mechanism:**

- Linux input/serio portion of the same Transformer-EC series;
- reply/fixup or fold into the next revision via email.

**Commit boundary:** one serio commit for OBF routing plus payload framing,
because both corrections complete the same keyboard command-response path.

**Missing qualification:** same v11+/current-tree rebase gate as K1; regenerate
maintainers/recipients from the final tree.

**Confidence:** high.

## Mesa patch inventory

### M0 — Grate source import and Mesa-25 integration

**Ownership split:**

- Grate driver/winsys implementation lineage: inherited from
  `grate-driver/mesa`;
- Mesa-25 API/build-system port and distinct `grate` registration: local work.

**Root problem:** the legacy Grate driver is Mesa-20-era code and cannot be
treated as an ABI-compatible DRI plug-in for a Mesa-25 userspace. The local port
adds a separate Gallium driver identity, `libdrm_tegra` dependency, loader
descriptor, build integration, and `grate_dri.so` alias.

**Primary upstream target / mechanism:**

- official Mesa: `https://gitlab.freedesktop.org/mesa/mesa`
- GitLab merge request, **only after maintainer interest in reviving the
  out-of-tree legacy hardware driver is established**.

The GitHub `grate-driver/mesa` repository is useful lineage/reference, but is
not a substitute for official Mesa integration.

**Proposed commit boundaries:**

1. provenance-preserving import of one exact legacy Grate source revision;
2. mechanical Mesa-current Gallium/API compatibility;
3. Meson / pipe-loader / DRI registration;
4. `libdrm_tegra` winsys/dependency adaptation.

**Missing qualification / risk:**

- identify and record the exact source commit for every imported legacy file;
- replay onto current Mesa main, not only 25.0.7;
- each commit must build and bisect;
- run Mesa unit tests and applicable Piglit/dEQP coverage;
- confirm maintainer appetite before investing in a large MR.

**Confidence:** high for official destination/mechanism; low-to-medium that a
complete driver revival would be accepted without prior maintainer discussion.

### M1 — Gallium state/resource/synchronization correctness

**Ownership:** local changes on top of the imported driver.

Observed local fix classes include:

- provide/retain blend-color and stencil-reference callbacks instead of NULL
  state-tracker calls;
- skip relocations for disabled render targets;
- restrict index-bias rejection to indexed draws;
- repair transfer/layer-stride behavior and mapped copy semantics;
- dma-buf FD import/export and offset validation;
- explicit channel fence/wait and Gallium flush lifetime handling;
- truthful capability and hardware-limit reporting.

**Evidence:** the first Nura GLES2 path reached EGL but exposed missing Gallium
callbacks and zero readback. Later resource/draw corrections produced real
RGB565 GR2D clear and GR3D triangle pixels; more demanding wlroots work later
exposed synchronization/layout/state failures, proving the simple triangle was
not sufficient qualification.

**Upstream target:** Mesa Grate driver, conditional on M0 being accepted.
Otherwise these belong in a maintained Grate lineage rather than Linux.

**Commit boundaries:** resource import/export + transfers; fence/flush lifetime;
state callbacks; capabilities/limits. Keep diagnostic logging out.

**Missing qualification:** focused contract tests, Mesa-current build/test, BO
lifetime/fault-delta testing, and compositor regression.

**Confidence:** medium.

### M2 — texture format/layout/sampler support

**Ownership:** local changes, with hardware-encoding knowledge also derived from
the Grate project.

**Root causes:**

- Mesa can request combined `SAMPLER_VIEW|RENDER_TARGET` resources;
- the old port accepted layouts whose pitch was not sampleable on Tegra20;
- BGRA/RGBA storage interpretation and texture descriptor/pitch behavior had to
  be made explicit;
- sampler-view reference ownership and texture instruction emission were
  incomplete;
- earlier candidates produced incorrect pixels and GPU timeouts.

The current source introduces a new `grate_texture.h` contract and sampler/
resource restrictions beyond the packaged legacy snapshot.

**Upstream target:** Mesa Grate driver if M0 is accepted; otherwise Grate
lineage. Hardware-encoding documentation potentially useful to
`grate-driver/grate` should be discussed separately from Mesa state-tracker
changes.

**Commit boundaries:** descriptor/format helpers + tests; resource/pitch
contract; sampler/view ownership; texture instruction emission.

**Missing qualification:** exact-hash texture oracle across supported formats,
padded pitch, filtering/wrap behavior, repeated upload/import, and kernel
fault-delta checks.

**Confidence:** medium.

### M3 — shader compiler, immediates, arithmetic and TEX lowering

**Ownership:** local changes on the legacy compiler.

Known changes include:

- record/upload vertex TGSI immediates at the hardware constant slots;
- fragment immediate support, later expanded with FP20 embedded constants;
- empty-MFU and zero-input linker handling;
- varying/export mapping and truthful shader limits;
- texture instruction lowering/encoding used by the Stage-D work.

**Evidence:** attribute-only triangle rendering passed while immediate-based
shaders initially failed; later immediate fixes passed the targeted hardware
probe. Subsequent arithmetic/TEX work advanced hardware coverage, while
compositor semantics still exposed broader defects.

**Upstream target:** Mesa Grate driver after M0 acceptance, otherwise the Grate
lineage.

**Commit boundary:** keep compiler/IR changes independent and test-backed; do
not bury them in an SL101-specific integration commit.

**Missing qualification:** instruction encoding unit vectors, broader shader
corpus, applicable Piglit/dEQP subset, and exact clean-branch hardware readback.

**Confidence:** medium.
