## Host build and patch

The isolated lane
`work/sl101-0077-prod-baseline-20261110/` retains a verbatim,
hash-checked copy of the Debian .100 kernel archive inputs; source was
**freshly extracted from the pristine upstream postmarketOS Grate
source archive** (no use of K76's patched source tree). Its original
`drivers/gpu/drm/grate/gem.c` SHA-256 is
`2c95b7815461ab361b528a4b81adc65149bc8f3303e69b5a78dadd6766834be2`.
The source snapshot matches the production package provenance.
The sole functional source change of the **runtime-selectable** candidate is:

`patches/linux-postmarketos-grate-7.0.1/0001-arm-cma-nokmap-lowmem-alias-runtime-AB.patch`

The patch:

1. Adds a writable builtin `cma_nokmap_remap` diagnostic parameter,
   default **off**.
2. In ARM32's `__alloc_from_contiguous()`, remaps the **lowmem
   direct-map alias** to coherent DMA attributes even when
   `DMA_ATTR_NO_KERNEL_MAPPING` suppresses a returned CPU virtual
   address, but **only** when the parameter is enabled.
3. Preserves the highmem path, regular mapping behavior, zeroing and
   flushing, and the Grate `DONT_KMAP` allocation policy.
4. Captures the decision per allocation and restores `PAGE_KERNEL`
   before releasing the relevant CMA pages, even after the global
   parameter has subsequently changed.
5. Keeps the atomic pool using the unchanged behavior (it requests
   `want_vaddr=true`).

The proposed release string for this diagnostic candidate is
`7.0.1-postmarketos-grate-attrfix2`, deliberately distinct from
both production and K76. Host recipe:
`work/sl101-0077-prod-baseline-20261110/build-production-attrfix2.sh`.
Build configuration comes from .100's `kernel7/config` and disables
debug info only to fit host disk; the compiler metadata/Rust/pahole
tool-version keys are regenerated by the local toolchain.

The patch has been dry-run-applied with zero fuzz to a separately
extracted pristine `dma-mapping.c`, and the modified ARM DMA object was
compiled and inspected for the built-in parameter symbol. The secondary
full build was stopped to avoid concurrent resource contention; its large
transient `source/` and `out/` directories have since been cleared.
**There is no built attrfix2 zImage.** Re-extraction and a new complete
build are required before using the A/B parameter on hardware.
No .100/.106 files were modified.

## Qualification gate (not yet executed)

First confirm that the built-in parameter is exposed and writable on
the experimental release; do not guess the sysfs module directory.
Then run same-boot ABBA for new BOs with parameter N/Y/Y/N (and
repeat), the same first-use copyback/prefill probes, and verified
per-run readback before/after every trial. Keep the graphics
qualification lock. A stock-production build does **not** expose the
K76-only `disable_auto_dont_kmap` diagnostic switch, so a matching
known-clean control requires another explicitly separate variant;
do not silently assume that switch exists.

A successful kernel build is not pixel-correctness evidence. The
mismatch of lowmem direct-map and DMA/user attributes remains a
**hypothesis**, not a proven cause. No reboot/APX/flash/deployment
has been authorized or performed by this lane.

## Completed stock-production build: dmafix1

The separately owned host build at
`work/sl101-prod-dma-init-20261110/` completed with `BUILD_SUCCESS`.
This uses the same verified .100 productive baseline, but is **not the
runtime-switchable patch** above. It contains two unconditional patches
archived under `patches/linux-postmarketos-grate-7.0.1/dmafix1/`:

1. `0001-arm-dma-cma-no-kmap-attributes.patch` — remap the lowmem direct
   alias in the ARM CMA allocator and restore it before free.
2. `0002-dma-direct-zero-no-kmap.patch` — explicit clear and synchronization
   for the generic direct-DMA no-mapping allocator. The ARM32 path for
   Grate was already shown to use arch/arm/mm/dma-mapping.c, so the second
   patch is not expected to explain that specific BO-corruption case.

Built release: `7.0.1-postmarketos-grate-dmafix1`.

- zImage: `out/arch/arm/boot/zImage`, SHA-256
  `315a49d41d590ee01eef59745fd0473e8e10f00fe547318f5b95d1219e0c4541`.
- DTB: `out/arch/arm/boot/dts/nvidia/tegra20-asus-sl101.dtb`, SHA-256
  `01fbb5a935e429c42dc5e2793049bbfc91ff3a6f73c15f2063e1fb0af1a289b0`
  (identical to archived productive DTB).
- Matching module stage: `modules/lib/modules/7.0.1-postmarketos-grate-dmafix1/`
  with **587 signed/compressed .ko.zst files**, generated `modules.dep`,
  and at least one verified `modinfo` vermagic matching the custom release.
- Build config differs from the archived .100 config only in localversion,
  debug info, and compiler/Rust/pahole capability metadata (19 generated
  keys); functional configuration is retained.
- Host `make check`: passed. Host `make test` was attempted but terminated
  before completion under load and is **not** reported as passed.
- Both devices remain unchanged, with .100 still reporting
  `7.0.1-postmarketos-grate`. No APX, boot installation, flash, or reboot.

The presence of a built dmafix1 kernel does not establish that the
first-use corruption is fixed: deployment, same-boot A/B hardware tests,
and regression/rollback verification are still required.
