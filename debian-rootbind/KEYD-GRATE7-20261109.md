# Debian SL101 .100: keyd, input/uinput and pending login-group activation

Date: 2026-11-09. Device `sltwrpbootdebian`, ASUS Eee Pad Slider
SL101, Debian 13.7 armhf/glibc on `/dev/mmcblk1p1`, booted
**normally** (no APX) with kernel `7.0.1-postmarketos-grate`.

This is a **live device observation**, not an inference from the Nura/
Alpine .106 tablet. All checks below were read-only; there was **no
keyd restart, remapping, reboot, module load or graphical session change**.

**Interpretation:** keyd service, uinput kernel facility and both virtual
input devices are operating under the new kernel. This **does not yet
prove physical key remapping**: operator-supervised typing of ordinary
letters, number row, modifier layer and the VT escape chords is still
required before declaring `keyd` end-to-end qualified. The package
installs `/usr/bin/keyd.rvaiya` rather than an executable named
`keyd` in `PATH`; use `systemctl status keyd` and
`/usr/bin/keyd.rvaiya` rather than assuming the Alpine command names.

## Persistent video/render group change (reboot not required immediately)

Following the Grate Mesa bring-up, the local `user` account was
updated with `usermod -aG video,render user`. As observed on .100:

    id user
    uid=1000(user) gid=1000(user) groups=1000(user),44(video),100(users),993(render)

But the existing, inherited SSH login group list was still:

    id
    uid=1000(user) gid=1000(user) groups=1000(user),100(users)

The account database is now correct; existing login sessions are
**not retroactively modified**. A full logout/new login through PAM
is enough; a later normal operator-approved reboot also establishes
fresh credentials. The reboot **has not been executed** for this task.

Before a future normal reboot, confirm no independent GPU/BO/mesa
workers are actively using .100, preserve the known 8-MiB LNX backup
and APX rescue path, and keep power stable. After the reboot, verify:

    uname -r
    findmnt -no SOURCE /
    id
    ls -l /dev/uinput /dev/input/event5 /dev/input/event6 /dev/input/event7
    systemctl is-active keyd
    /opt/sl101-debian-rootbind/bin/sl101-grate prod70 check

Expected kernel/root are `7.0.1-postmarketos-grate` and
`/dev/mmcblk1p1`; ordinary login `id` should now include video
and render, and the Grate check should say `Grate / Tegra` (not
softpipe). The physical keyboard should remain functional with and
without the meta layer. Do not test virtual terminal switching while
remote SSH is the **only** recovery mechanism.

## Related caveat

The keyd ability to create a virtual input device does **not** prove
that a graphical Sway/Cog session is configured. The Debian user
`/home/user/.config/sway/config` was absent on the same boot and
headless `sway -C` could not claim seat/VT. Keep those qualifications
separate from the now confirmed keyd daemon/uinput functionality.

See `docs/sl101-debian-grate-0070-bringup-20261109.md` for Mesa/GBM
and `docs/sl101-asus-apx-free-boot-20261109.md` for preserved boot
and rollback geometry.
